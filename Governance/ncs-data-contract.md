# Never Coming Soon
## Ideation Data Contract v1.0

## 1. Purpose

This document defines the Google Sheets contract for the Ideation workflow and the handoff contract to Generation.

The Sheet should remain lean.

Every field must improve one of three things:

1. creative memory
2. concept quality or curation
3. handoff quality

If a field does not materially improve one of those, do not add it.

## 2. Row model

**One row equals one Never Coming Soon concept.**

The same row persists from raw seed through Development Select.

## 3. Canonical columns

Use these columns in this order unless implementation needs require a minor change.

1. `idea_id`
2. `created_at`
3. `status`
4. `ideation_mode`
5. `working_title`
6. `format`
7. `genre`
8. `creative_tags_json`
9. `premise`
10. `creative_kernel`
11. `why_exciting`
12. `short_pitch`
13. `characters_json`
14. `story_core_json`
15. `signature_scenes_json`
16. `fingerprint`
17. `duplicate_check_json`
18. `concept_score_json`
19. `interrogation_json`
20. `development_packet_json`
21. `human_notes`

## 4. Field definitions

### idea_id

Permanent identifier generated by n8n.

Recommended pattern:

`NCS-I-000001`

Never reuse an ID.

### created_at

ISO 8601 timestamp.

### status

Allowed values:

- `RAW`
- `DEVELOP`
- `PROMISING`
- `HOLD`
- `DUPLICATE`
- `DEVELOPMENT_SELECT`

Generation may later add downstream statuses in a separate workflow if desired.

### ideation_mode

Allowed examples:

- `character_first`
- `relationship_first`
- `world_first`
- `situation_first`
- `genre_first`
- `scene_first`
- `ending_first`
- `truth_first`
- `discovery_first`
- `title_first`

### working_title

Provisional title only.

Generation has full authority to change it.

### format

Allowed values:

- `FILM`
- `SERIES`
- `LIMITED_SERIES`

Provisional until Generation confirms.

### genre

Primary genre string.

Hybrid or secondary genre information may live inside `creative_tags_json`.

### creative_tags_json

Compact structured context.

Recommended shape:

```json
{
  "secondary_genre": null,
  "arena": null,
  "tone": [],
  "era": null,
  "setting": null,
  "scale": null,
  "audience": null,
  "narrative_engine": []
}
```

Do not create separate columns for these unless future workflow pain justifies it.

### premise

One-sentence current concept.

### creative_kernel

The core creative reason the concept is worth preserving.

This is the most important handoff field.

### why_exciting

Short statement explaining what makes the idea fun, emotionally promising, culturally interesting, or otherwise worth developing.

### short_pitch

Usually 75 to 200 words.

Enough to understand the current concept without pretending the story is locked.

### characters_json

Provisional character possibilities.

Recommended shape:

```json
{
  "protagonist": {
    "name": null,
    "core": null,
    "desire": null,
    "contradiction": null
  },
  "central_relationship": {
    "with": null,
    "dynamic": null
  },
  "supporting": []
}
```

Names may be null. Generation may replace any character.

### story_core_json

Provisional story possibilities.

Recommended shape:

```json
{
  "possible_setup": null,
  "dramatic_question": null,
  "possible_escalations": [],
  "possible_climax_direction": null,
  "possible_ending_direction": null,
  "tv_engine": null,
  "season_one_direction": null
}
```

These are possibilities, not locked beats.

### signature_scenes_json

Array of 2 to 4 scene seeds that indicate creative fertility.

### fingerprint

Deterministic hash generated by n8n from a normalized structural signature.

Agents should output the normalized signature, not the hash itself.

### duplicate_check_json

Recommended shape:

```json
{
  "status": "CLEAR",
  "nearest": [],
  "judgment": null
}
```

Allowed status values:

- `CLEAR`
- `OVERLAP`
- `DUPLICATE`

### concept_score_json

Recommended shape:

```json
{
  "desire": 0,
  "fertility": 0,
  "human_pull": 0,
  "distinctive_spark": 0,
  "emotional_genre_promise": 0,
  "overall_potential": 0,
  "would_develop": "YES",
  "notes": null
}
```

Scores use a 1 to 10 scale.

`would_develop` allowed values:

- `YES`
- `MAYBE`
- `NO`

### interrogation_json

Light expansion of `DEVELOP` concepts.

Recommended shape:

```json
{
  "human_anchor": null,
  "possible_story_directions": [],
  "scenes_that_appear_naturally": [],
  "obvious_bad_version": null,
  "creative_opportunity": null,
  "format_note": null,
  "open_questions": []
}
```

### development_packet_json

Only populated for `DEVELOPMENT_SELECT` rows.

This is the complete handoff object to Generation.

### human_notes

Freeform human editor notes.

Agents may read this field when instructed but should never overwrite human content unless explicitly authorized.

## 5. Ownership

### Ideation owns provisionally

- working title
- format
- genre
- creative tags
- premise
- characters
- story possibilities
- scene seeds

### Generation owns final creative development

Generation may materially revise all provisional fields.

The Development Packet is not a lock.

## 6. Protected intent

Generation should pay special attention to:

- `creative_kernel`
- `why_exciting`
- emotional / genre promise embedded in the packet

These explain why the concept was selected.

Generation should preserve or improve them, not obey them mechanically.

## 7. JSON storage rules

Store structured objects as valid compact JSON strings in the relevant Sheet cell.

Use `null` for unknown scalar values.

Use `[]` for empty arrays.

Do not store pseudo-JSON.

Do not embed Markdown fences in Sheet JSON fields.

## 8. Overwrite rules

- Preserve `idea_id` and `created_at` forever.
- Preserve `human_notes` unless a human explicitly changes it.
- Do not overwrite a non-empty `development_packet_json` without an explicit re-development action.
- Status changes must be explicit.

## 9. Minimalism rule

Do not add a new Sheet column merely because an agent can produce more data.

Add a field only after repeated workflow pain demonstrates that the new field will improve creative quality or reliability.
