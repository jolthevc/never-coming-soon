# Never Coming Soon
## Ideation Data Contract v1.1

## 1. Purpose

This document defines the Google Sheets contract for the Ideation workflow and the handoff contract to Generation.

The Sheet should remain lean.

Every field must improve one of three things:

1. creative memory
2. concept quality or curation
3. handoff quality

If a field does not materially improve one of those, do not add it.

## 2. Row model

**One row equals one Never Coming Soon concept.**

The same row persists from raw seed through Development Select.

Use `idea_id` as the durable row key. Never rely on visible row number after filtering or sorting.

## 3. Canonical columns

Use these columns in this exact order for v1.1.

1. `idea_id`
2. `created_at`
3. `status`
4. `ideation_mode`
5. `working_title`
6. `format`
7. `genre`
8. `creative_tags_json`
9. `premise`
10. `creative_kernel`
11. `why_exciting`
12. `short_pitch`
13. `characters_json`
14. `story_core_json`
15. `signature_scenes_json`
16. `fingerprint`
17. `duplicate_check_json`
18. `concept_score_json`
19. `interrogation_json`
20. `development_packet_json`
21. `human_notes`

Do not add a column merely to expose another agent output.

## 4. Field definitions

### idea_id

Permanent identifier generated by n8n.

Recommended pattern:

`NCS-I-000001`

Generate IDs by reading the maximum existing numeric suffix and reserving the next contiguous block before parallel writes.

Never reuse an ID.

### created_at

ISO 8601 timestamp.

Use one consistent timezone, preferably UTC, at the orchestration layer.

### status

Allowed values:

- `RAW`
- `DEVELOP`
- `PROMISING`
- `HOLD`
- `DUPLICATE`
- `DEVELOPMENT_SELECT`

Generation may later use an additional downstream status field if the workflow genuinely needs one. Do not overload this ideation status casually.

### ideation_mode

Allowed values:

- `character_first`
- `relationship_first`
- `world_first`
- `situation_first`
- `genre_first`
- `scene_first`
- `ending_first`
- `truth_first`
- `discovery_first`
- `title_first`

### working_title

Provisional title only.

Generation has full authority to change it.

### format

Allowed values:

- `FILM`
- `SERIES`
- `LIMITED_SERIES`

Provisional until Generation confirms.

### genre

Primary genre string.

Hybrid or secondary genre information lives inside `creative_tags_json`.

### creative_tags_json

Compact structured context.

Canonical shape after a seed has been normalized:

```json
{
  "secondary_genre": null,
  "arena": null,
  "tone": [],
  "era": null,
  "setting": null,
  "scale": null,
  "audience": null,
  "narrative_engine": [],
  "memory_signature": {
    "format": null,
    "genre": null,
    "arena": null,
    "protagonist_archetype": null,
    "central_relationship": null,
    "core_situation": null,
    "story_engine": null,
    "setting": null
  }
}
```

`memory_signature` is preserved here because it materially improves future duplicate retrieval without creating another Sheet column.

The LLM may propose the normalized signature. n8n canonicalizes it and writes the canonical form into this object.

### premise

One-sentence current concept.

Clear enough to understand in one read.

### creative_kernel

The core creative reason the concept is worth preserving.

This is the most important handoff field.

### why_exciting

Short statement explaining the actual source of entertainment, emotion, chemistry, tension, comedy, spectacle, or creative opportunity.

Avoid generic praise.

### short_pitch

Usually 75 to 200 words.

Enough to understand the current concept without pretending the story is locked.

Normally blank at RAW stage and populated during Idea Expansion.

### characters_json

Provisional character possibilities.

Canonical shape once populated:

```json
{
  "protagonist": {
    "name": null,
    "core": null,
    "desire": null,
    "contradiction": null
  },
  "central_relationship": {
    "with": null,
    "dynamic": null
  },
  "supporting": []
}
```

Names may be null. Generation may replace any character.

Normally blank at RAW stage.

### story_core_json

Provisional story possibilities.

Canonical shape once populated:

```json
{
  "possible_setup": null,
  "dramatic_question": null,
  "possible_escalations": [],
  "possible_climax_direction": null,
  "possible_ending_direction": null,
  "tv_engine": null,
  "season_one_direction": null
}
```

These are possibilities, not locked beats.

Normally blank at RAW stage.

### signature_scenes_json

Array of 2 to 4 scene seeds that indicate creative fertility.

Normally blank at RAW stage.

### fingerprint

Deterministic SHA-256 hash generated by n8n from the canonical `memory_signature`.

Agents should output the normalized signature, not the hash itself.

Regenerate the fingerprint after Idea Expansion because expansion may materially change the concept.

### duplicate_check_json

Canonical shape:

```json
{
  "status": "CLEAR",
  "duplicate_of": null,
  "similar_ideas": [],
  "judgment": null
}
```

Allowed status values:

- `CLEAR`
- `OVERLAP`
- `DUPLICATE`

For `DUPLICATE`, `duplicate_of` should identify the surviving or historical concept when known.

The latest valid audit is stored in this cell. Expanded concepts receive a second audit before Development Select.

### concept_score_json

Canonical shape:

```json
{
  "desire": 8,
  "fertility": 8,
  "human_pull": 7,
  "distinctive_spark": 8,
  "emotional_genre_promise": 8,
  "overall_potential": 8,
  "would_develop": "YES",
  "notes": "Strong seed with clear room to develop."
}
```

Scores use a 1 to 10 scale.

`would_develop` allowed values:

- `YES`
- `MAYBE`
- `NO`

Scores are diagnostic, not arithmetic gates.

Keep the scorecard's `would_develop` judgment consistent with the row status assigned by the Curator:

- `DEVELOP` pairs with `YES`
- `PROMISING` pairs with `YES` or `MAYBE`
- `HOLD` pairs with `MAYBE` or `NO`

### interrogation_json

Light expansion of `DEVELOP` concepts.

Canonical shape:

```json
{
  "human_anchor": null,
  "possible_story_directions": [],
  "scenes_that_appear_naturally": [],
  "obvious_bad_version": null,
  "creative_opportunity": null,
  "format_note": null,
  "open_questions": []
}
```

### development_packet_json

Only populated for `DEVELOPMENT_SELECT` rows.

This is the complete creative brief handed to Generation.

The packet must preserve creative optionality rather than pretending the production is already solved.

### human_notes

Freeform human editor notes.

Agents may read this field when relevant but should never overwrite human content unless explicitly authorized.

## 5. Stage population rules

### RAW

Expected populated fields:

- identity fields
- ideation mode
- working title
- format
- genre
- creative tags, including memory signature
- premise
- creative kernel
- why exciting
- fingerprint
- duplicate check once audited

Later-development fields may remain blank.

### DEVELOP / PROMISING / HOLD

Add `concept_score_json`.

`DEVELOP` rows may later receive expanded creative fields.

### Expanded DEVELOP

Populate:

- short_pitch
- characters_json
- story_core_json
- signature_scenes_json
- interrogation_json
- refreshed creative tags and memory signature
- refreshed fingerprint
- refreshed duplicate check

### DEVELOPMENT_SELECT

Populate `development_packet_json`.

## 6. Ownership

### Ideation owns provisionally

- working title
- format
- genre
- creative tags
- premise
- characters
- story possibilities
- scene seeds

### Generation owns final creative development

Generation may materially revise all provisional fields.

The Development Packet is not a lock.

## 7. Protected intent

Generation should pay special attention to:

- `creative_kernel`
- `why_exciting`
- emotional and genre promise embedded in the packet

These explain why the concept was selected.

Generation should preserve or improve them, not obey them mechanically.

## 8. JSON storage rules

Store structured objects as valid compact JSON strings in the relevant Sheet cell.

Use `null` for unknown scalar values inside a populated JSON object.

Use `[]` for known-empty arrays inside a populated JSON object.

If a structured field has not yet been produced at that workflow stage, leave the Sheet cell blank rather than writing `{}` or `null` as text.

Do not store pseudo-JSON.

Do not embed Markdown fences in Sheet JSON fields.

Do not double-stringify. A Sheet cell should contain the JSON text once. On read, parse it once.

## 9. Overwrite rules

- Preserve `idea_id` and `created_at` forever.
- Preserve `human_notes` unless a human explicitly changes it.
- Do not overwrite a non-empty `development_packet_json` without an explicit re-development action.
- Status changes must be explicit.
- Update rows by `idea_id`, not visible row number.
- When Idea Expansion changes the memory signature, refresh both `fingerprint` and `duplicate_check_json` before Development Select.

## 10. Minimalism rule

Do not add a new Sheet column merely because an agent can produce more data.

Add a field only after repeated workflow pain demonstrates that the new field will improve creative quality or reliability.
